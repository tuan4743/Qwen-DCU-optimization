# 00 · 成果总览

> 30 秒版:我们在**国产海光 DCU(gfx936)**上,把 **Qwen3.5-27B** 的 vLLM 推理服务从"能跑"优化到"能打"——长上下文吞吐最高提升 **2.63 倍**,首字时延下降 **59%**,且全部改动公开、可复现、有原始数据支撑。

## 最终成绩(官方评测口径)

| 指标 | 优化前 | 优化后 | 提升 |
|---|---|---|---|
| 吞吐 4-8K | 12.20 tok/s | **19.56 tok/s** | **+60%** |
| 吞吐 8-16K | 8.81 tok/s | **14.92 tok/s** | **+69%** |
| 吞吐 16-32K | 4.64 tok/s | **12.22 tok/s** | **+163%** |
| P99 首 token 时延(TTFT) | 4789.70 ms | **1964.41 ms** | **−59%** |
| P99 单 token 时延(TPOT) | 69.00 ms | **45.14 ms** | **−35%** |

## 我们做了什么

| 轮 | 做了什么 | 4-8K 吞吐 |
|---|---|---|
| 一 | **点亮瘦 GEMM 算子链** + 修好 Prefill 大瓦片导致的共享内存爆掉 | 12.20 → 16.20(**+33%**,突破性一步) |
| 二 | 长上下文调优:自适应 Flash-Decoding、非对称 Prefill 瓦片 | 保持 16.05,长段回升 |
| 三 | GDN/FLA 定参与 BLOCK_M 修复 | 17.25;16-32K 从 3.64 → 6.99 |
| 四 | 大瓦片注意力 + Decode 融合首步 | 19.12;TTFT 首破 2s |
| 五 | **算子融合收口:跨阶段 in_proj 融合 + 融合 Chunk 预处理** | **19.56 / 14.92 / 12.22** |

**最有价值的三件事**
1. **国产适配层的打通**:国内卡生态远未成熟,光是让"能跑"就需要解决架构白名单缺失、矩阵指令限制、工具链缺件等一堆"非 CUDA 特色坑"——我们在 README「Hardware Setup」里把坑和修法写全了,这是全仓库最有复用价值的部分。
2. **瘦 GEMM 路由(LLMM1 激活)**:decode 的投影 GEMM 从 500us 级降到 127-188us,是破局点。
3. **算子融合(第四、五章)**:跨阶段权重拼接 + 融合 Chunk 预处理,单轮收益最大,且**不需要重新编译 `_rocm_C.so`**,移植性好。
